# Phase 6: Jenkins as code, GitHub webhook, multibranch pipeline, required check

**Goal:** a Jenkins server that is installed **and configured entirely by code** (no clicking in its setup screens). It tests every branch and pull request automatically, and GitHub refuses to merge a PR until Jenkins says ✅.

**Done when:** opening a PR makes Jenkins run the tests, GitHub shows `continuous-integration/jenkins/pr-merge ✓`, and the ruleset requires that check.

---

## 6.1 The big picture

```text
 you: git push / open PR
        │
        ▼
 GitHub ──webhook (HTTPS POST, signed with a secret)──► https://jenkins.<ip>.sslip.io/github-webhook/
        ▲                                                   │  Caddy → Jenkins (127.0.0.1:8080)
        │                                                   ▼
        │                                     multibranch job "notes-devops"
        │                                       finds the branch/PR, reads its Jenkinsfile
        │                                       runs: docker compose -f compose.ci.yml run tests
        │                                                   │
        └──── commit status: ✓ / ✗ ◄────────────────────────┘  (uses the GitHub token)

 Ruleset protect-main: "Require status checks to pass: continuous-integration/jenkins/pr-merge"
 → the Merge button stays blocked until Jenkins reports ✓
```

### Words used in this phase

| Word | Simple meaning |
|---|---|
| **Jenkins** | a program that runs jobs (build, test, deploy) automatically |
| **Job** | one thing Jenkins can run |
| **Pipeline** | a job described as code, in a file called `Jenkinsfile`, with **stages** (Lint & Test, Build, Deploy ...) |
| **Multibranch pipeline** | a "folder" job that creates one pipeline **per branch and per pull request** automatically, for every branch that has a `Jenkinsfile` |
| **Branch indexing / scan** | Jenkins asks GitHub "which branches and PRs exist?" and creates/removes sub-jobs |
| **Webhook** | GitHub calls a Jenkins URL the moment something happens (push, PR), so Jenkins doesn't have to keep asking |
| **Commit status / check** | a ✓ or ✗ that Jenkins attaches to a commit on GitHub |
| **Required status check** | a ruleset setting: merging is blocked until that check is ✓ |
| **Plugin** | an add-on that gives Jenkins features (GitHub support, pipelines, JCasC ...) |
| **JCasC** (Jenkins Configuration as Code) | a plugin that reads Jenkins' settings (users, security, credentials, jobs) from a **YAML file** |
| **Job DSL** | a plugin that creates jobs from a small Groovy script; JCasC uses it to create our multibranch job |
| **Credential** | a secret stored inside Jenkins (token, password), referenced by an ID such as `github-token` |
| **Executor** | a slot that runs one build at a time; we have 2 on the Jenkins server itself |
| **Controller** | the main Jenkins server (the old name was "master") |

## 6.2 Beginner vs intermediate Jenkins

| Beginner project | Now |
|---|---|
| Jenkins in Docker, set up by clicking through the setup wizard | Jenkins installed **natively** by Ansible from the official apt repository |
| Plugins installed by clicking | plugins listed in `plugins.txt`, installed by the **plugin installation manager** |
| Admin user created by hand, password in your head | admin password generated by **Terraform**, stored in **SSM**, written by Ansible |
| One pipeline job created by hand | **multibranch** job created by **JCasC + Job DSL** |
| "Build Now" or polling | **GitHub webhook** with a secret signature |
| No link back to GitHub | Jenkins sets a **commit status**; GitHub **requires** it before merge |
| HTTP on port 8080 | **HTTPS** through Caddy; Jenkins listens on `127.0.0.1` only |

If the Jenkins server is destroyed, one `ansible-playbook` run rebuilds it **exactly**, with no clicking at all.

## 6.3 Decisions in this phase

| # | Decision | Why |
|---|---|---|
| P6-1 | **Jenkins LTS** from `pkg.jenkins.io/debian-stable` | LTS = "long-term support": tested, slower-changing releases for servers. Weekly releases change every week |
| P6-2 | New repository key **`jenkins.io-2026.key`** | Jenkins changed its signing key for LTS 2.541.1 and later (Dec 2025); the old 2023 key would fail |
| P6-3 | **Java 21** (`openjdk-21-jre-headless`) | Jenkins needs Java 21 or 25; Java 17 is no longer supported. "headless" = no graphics libraries (it's a server) |
| P6-4 | Systemd **override** file instead of editing the service | package updates never overwrite our settings |
| P6-5 | `-Djenkins.install.runSetupWizard=false` | no setup wizard: everything comes from JCasC |
| P6-6 | `JENKINS_LISTEN_ADDRESS=127.0.0.1` | Jenkins is only reachable through Caddy (HTTPS); port 8080 is never exposed |
| P6-7 | `policy-rc.d` blocks the start during the **first** install | otherwise apt starts Jenkins immediately, **without security**, for a minute or so, on a public HTTPS address that bots scan |
| P6-8 | Plugins from `plugins.txt` with the **plugin installation manager** (pinned version 2.15.0) | the official tool; it resolves dependencies and picks versions that fit our Jenkins version |
| P6-9 | **JCasC** for all settings | settings are in Git, reviewed in PRs, and reproducible |
| P6-10 | Secrets as **files** in `/var/lib/jenkins/casc-secrets` (mode 0700/0600), referenced as `${name}` | secrets never appear in the JCasC file, in Git, or in Ansible output (`no_log`) |
| P6-11 | Admin password + webhook secret from **Terraform** (`random_password` → SSM) | nobody chooses or types them; new ones every session |
| P6-12 | GitHub token stored in SSM **by hand** (not in Terraform) | it comes from GitHub, not AWS; keeping it out of Terraform keeps it out of the state file and tfvars. It survives `terraform destroy` |
| P6-13 | **Fine-grained** token, one repo, minimum permissions, 90 days | if it leaks, it can only read this repo and set statuses, and it expires by itself |
| P6-14 | One local user `admin`, "logged-in users can do anything", no sign-up, anonymous sees nothing | simplest secure setup for one person. A team would use matrix-based permissions or GitHub login |
| P6-15 | Agent port disabled (`slaveAgentPort: -1`) | we have no separate build agents; one less open door |
| P6-16 | Builds run on the controller (2 executors) | simple and cheap. **Known risk:** a build runs as user `jenkins` and could read Jenkins' files; acceptable because only our own branches are built. The advanced level uses separate agents |
| P6-17 | **No fork PRs** discovered | the repo is public: a stranger's PR could change the Jenkinsfile and run commands on our server |
| P6-18 | Branch strategy 1 (skip branches that are also PRs), PR strategy 1 (**merge** with the target branch) | no double builds; a PR is tested **as if it were already merged into main**, which catches conflicts with newer main |
| P6-19 | Webhook created with `gh api`, events `push` + `pull_request`, with a **secret** | Jenkins rejects calls that aren't signed with the secret (protects against fake webhooks) |
| P6-20 | Daily scan as a backup (`periodicFolderTrigger 1d`) | if a webhook is missed, Jenkins still catches up |
| P6-21 | GitHub API: `ThrottleOnOver` | Jenkins only slows down when close to GitHub's rate limit, instead of always spreading requests out |
| P6-22 | `jenkins` user in the `docker` group | the pipeline runs `docker compose`. Note: equal to root on this server |
| P6-23 | Tests run with the **same command** as on the Mac (`compose.ci.yml`) | "works on my machine" = "works in CI" |
| P6-24 | Unique compose project name per build (`ci-<branch>-<build>`) + `down -v --rmi local` afterwards | two builds never share containers; no leftover containers, volumes or images fill the disk |
| P6-25 | Required check = `continuous-integration/jenkins/pr-merge` | that's the name the GitHub Branch Source plugin uses for PR builds |

## 6.5 Terraform: two new secrets

Added to `envs/prod/main.tf`:

```hcl
resource "random_password" "jenkins_admin" {
  length  = 24
  special = false
}

resource "aws_ssm_parameter" "jenkins_admin_password" {
  name  = "${local.ssm_prefix}/jenkins_admin_password"
  type  = "SecureString"
  value = random_password.jenkins_admin.result
}

resource "random_password" "github_webhook_secret" {
  length  = 40
  special = false
}

resource "aws_ssm_parameter" "github_webhook_secret" {
  name  = "${local.ssm_prefix}/github_webhook_secret"
  type  = "SecureString"
  value = random_password.github_webhook_secret.result
}
```

`special = false`: letters and digits only, so they can be typed and pasted safely anywhere (URLs, YAML, shell). 24 random letters/digits are still far too many to guess.

<sub>File: `infra/ansible/roles/jenkins/tasks/main.yml`</sub>

```yaml
- name: Check that the GitHub settings are set
  ansible.builtin.assert:
    that:
      - jenkins_github_owner | length > 0
      - jenkins_github_repo | length > 0
      - jenkins_github_user | length > 0
    fail_msg: "Set jenkins_github_owner, jenkins_github_repo and jenkins_github_user in group_vars/jenkins.yml"

- name: Install Java and git
  ansible.builtin.apt:
    name:
      - fontconfig
      - "{{ jenkins_java_package }}"
      - git
    state: present

- name: Add the official Jenkins LTS repository
  ansible.builtin.deb822_repository:
    name: jenkins
    types: deb
    uris: https://pkg.jenkins.io/debian-stable
    suites: binary/
    signed_by: https://pkg.jenkins.io/debian-stable/jenkins.io-2026.key

- name: Create the systemd override folder
  ansible.builtin.file:
    path: /etc/systemd/system/jenkins.service.d
    state: directory
    owner: root
    group: root
    mode: "0755"

- name: Jenkins service settings (no setup wizard, localhost only, JCasC)
  ansible.builtin.template:
    src: override.conf.j2
    dest: /etc/systemd/system/jenkins.service.d/override.conf
    owner: root
    group: root
    mode: "0644"
  notify: Restart jenkins

- name: Check if Jenkins is already installed
  ansible.builtin.stat:
    path: "{{ jenkins_war }}"
  register: jenkins_war_file

- name: Do not start services during the first install
  ansible.builtin.copy:
    dest: /usr/sbin/policy-rc.d
    content: |
      #!/bin/sh
      exit 101
    owner: root
    group: root
    mode: "0755"
  when: not jenkins_war_file.stat.exists

- name: Install Jenkins
  ansible.builtin.apt:
    name: jenkins
    state: present
    update_cache: true

- name: Allow services to start again
  ansible.builtin.file:
    path: /usr/sbin/policy-rc.d
    state: absent

- name: Create the JCasC folders
  ansible.builtin.file:
    path: "{{ item.path }}"
    state: directory
    owner: jenkins
    group: jenkins
    mode: "{{ item.mode }}"
  loop:
    - { path: "{{ jenkins_casc_dir }}", mode: "0750" }
    - { path: "{{ jenkins_secrets_dir }}", mode: "0700" }

- name: Check that the secrets exist in SSM Parameter Store
  ansible.builtin.assert:
    that: query('amazon.aws.ssm_parameter', jenkins_ssm_prefix ~ '/' ~ item, region=jenkins_aws_region, on_missing='skip') | select | list | length == 1
    fail_msg: "Missing SSM parameter {{ jenkins_ssm_prefix }}/{{ item }}"
    quiet: true
  loop:
    - jenkins_admin_password
    - github_token
    - github_webhook_secret

- name: Write secrets from SSM Parameter Store
  ansible.builtin.copy:
    dest: "{{ jenkins_secrets_dir }}/{{ item.file }}"
    content: "{{ lookup('amazon.aws.ssm_parameter', jenkins_ssm_prefix ~ '/' ~ item.param, region=jenkins_aws_region) }}"
    owner: jenkins
    group: jenkins
    mode: "0600"
  loop:
    - { file: admin_password, param: jenkins_admin_password }
    - { file: github_token, param: github_token }
    - { file: github_webhook_secret, param: github_webhook_secret }
  loop_control:
    label: "{{ item.file }}"
  no_log: true
  notify: Restart jenkins

- name: Download the plugin installation manager
  ansible.builtin.get_url:
    url: "{{ jenkins_plugin_manager_url }}"
    dest: "{{ jenkins_plugin_manager_jar }}"
    owner: root
    group: root
    mode: "0644"

- name: Copy the plugin list
  ansible.builtin.copy:
    src: plugins.txt
    dest: "{{ jenkins_home }}/plugins.txt"
    owner: jenkins
    group: jenkins
    mode: "0644"
  register: jenkins_plugin_list

- name: Check if the plugins are installed
  ansible.builtin.stat:
    path: "{{ jenkins_home }}/plugins/configuration-as-code.jpi"
  register: jenkins_casc_plugin

- name: Install the plugins (and their dependencies)
  ansible.builtin.command:
    cmd: >-
      java -jar {{ jenkins_plugin_manager_jar }}
      --war {{ jenkins_war }}
      --plugin-download-directory {{ jenkins_home }}/plugins
      --plugin-file {{ jenkins_home }}/plugins.txt
  become: true
  become_user: jenkins
  when: jenkins_plugin_list is changed or not jenkins_casc_plugin.stat.exists
  changed_when: true
  notify: Restart jenkins

- name: Write the Jenkins configuration (JCasC)
  ansible.builtin.template:
    src: jenkins.yaml.j2
    dest: "{{ jenkins_casc_dir }}/jenkins.yaml"
    owner: jenkins
    group: jenkins
    mode: "0640"
  notify: Restart jenkins

- name: Allow Jenkins to use Docker
  ansible.builtin.user:
    name: jenkins
    groups: docker
    append: true
  notify: Restart jenkins

- name: Apply pending restarts now
  ansible.builtin.meta: flush_handlers

- name: Start Jenkins now and at boot
  ansible.builtin.systemd_service:
    name: jenkins
    state: started
    enabled: true
    daemon_reload: true

- name: Wait until Jenkins answers
  ansible.builtin.uri:
    url: http://127.0.0.1:8080/login
    status_code: 200
  register: jenkins_login_page
  until: jenkins_login_page.status == 200
  retries: 40
  delay: 5
```

| Task | What and why |
|---|---|
| assert GitHub settings | stop early with a clear message if `group_vars/jenkins.yml` is incomplete |
| Java + git | Jenkins is a Java program; `git` checks out the code; `fontconfig` is needed by Jenkins for some graphics (charts) |
| Jenkins repository | `suites: binary/` = Jenkins uses a simple "flat" repository (no components like `main`) |
| systemd override | the settings below, without touching the package's own service file |
| `stat` + `policy-rc.d` | on the **first** install only: a file that tells apt "don't start services now" (exit code 101). Removed right after the install |
| JCasC folders | `casc` (0750) for the config, `casc-secrets` (0700) so only the `jenkins` user can open it |
| Check secrets exist | clear error "Missing SSM parameter ..." instead of a hidden failure (the next task hides its output) |
| Write secrets | `lookup('amazon.aws.ssm_parameter', ...)` runs **on the control node** (your Mac, using your AWS login), reads and decrypts the value, and writes it to a file with mode 0600. `no_log: true` = never print the values. `loop_control.label` = print only the file name |
| Plugin manager | downloads the official tool once |
| plugins.txt + install | the install runs only when the list changed or on the first install (idempotent); runs as user `jenkins` so files belong to Jenkins |
| JCasC file | the template below |
| docker group | so pipelines can use Docker |
| `flush_handlers` | run the "Restart jenkins" handler **now** (not at the end of the play), so the next tasks see the new Jenkins |
| Start + enable | runs at boot |
| Wait (`uri` + `until`) | ask `http://127.0.0.1:8080/login` every 5 s, up to 40 times, until it answers 200 (Jenkins needs ~30–60 s to start) |

## 6.7 JCasC: the whole Jenkins configuration in one file

<sub>File: `infra/ansible/roles/jenkins/templates/jenkins.yaml.j2`</sub>

```jinja
# Managed by Ansible (Jenkins Configuration as Code).
# Changes made in the Jenkins web UI are overwritten at the next restart.
# ${name} values are read from files in {{ jenkins_secrets_dir }}.

jenkins:
  systemMessage: "notes-devops CI - configured as code. Do not change settings in the UI."
  numExecutors: {{ jenkins_executors }}
  mode: NORMAL
  slaveAgentPort: -1
  securityRealm:
    local:
      allowsSignup: false
      users:
        - id: "{{ jenkins_admin_user }}"
          password: "${admin_password}"
  authorizationStrategy:
    loggedInUsersCanDoAnything:
      allowAnonymousRead: false

security:
  globalJobDslSecurityConfiguration:
    useScriptSecurity: false

unclassified:
  gitHubConfiguration:
    apiRateLimitChecker: ThrottleOnOver
  location:
    url: "{{ jenkins_url }}"
  gitHubPluginConfig:
    hookSecretConfigs:
      - credentialsId: "github-webhook-secret"

credentials:
  system:
    domainCredentials:
      - credentials:
          - usernamePassword:
              scope: GLOBAL
              id: "github-token"
              username: "{{ jenkins_github_user }}"
              password: "${github_token}"
              description: "GitHub fine-grained token: read the repo, set commit status"
          - string:
              scope: GLOBAL
              id: "github-webhook-secret"
              secret: "${github_webhook_secret}"
              description: "Checks that webhooks really come from GitHub"

jobs:
  - script: |
      multibranchPipelineJob('{{ jenkins_github_repo }}') {
        displayName('{{ jenkins_github_repo }}')
        description('Every branch and pull request of {{ jenkins_github_owner }}/{{ jenkins_github_repo }}')
        branchSources {
          branchSource {
            source {
              github {
                id('{{ jenkins_github_repo }}')
                repoOwner('{{ jenkins_github_owner }}')
                repository('{{ jenkins_github_repo }}')
                repositoryUrl('https://github.com/{{ jenkins_github_owner }}/{{ jenkins_github_repo }}')
                configuredByUrl(true)
                credentialsId('github-token')
                traits {
                  gitHubBranchDiscovery {
                    strategyId(1)
                  }
                  gitHubPullRequestDiscovery {
                    strategyId(1)
                  }
                }
              }
            }
          }
        }
        orphanedItemStrategy {
          discardOldItems {
            numToKeep(10)
          }
        }
        triggers {
          periodicFolderTrigger {
            interval('1d')
          }
        }
      }
```

| Part | Meaning |
|---|---|
| `jenkins.systemMessage` | banner on the dashboard |
| `numExecutors: 2` | two builds at the same time |
| `securityRealm.local` | Jenkins' own user database; `allowsSignup: false` = nobody can register |
| `authorizationStrategy.loggedInUsersCanDoAnything` | logged in = full rights; `allowAnonymousRead: false` = strangers see only the login page |
| `security.globalJobDslSecurityConfiguration.useScriptSecurity: false` | our Job DSL script comes from our own Git repo through Ansible, so it doesn't need approval in the UI |
| `unclassified.location.url` | Jenkins' public address, used in links (for example the "Details" link on GitHub) |
| `gitHubPluginConfig.hookSecretConfigs` | check every webhook's signature with the secret |
| `gitHubConfiguration.apiRateLimitChecker` | GitHub API rate-limit behaviour |
| `credentials` | `github-token` (username + token) and `github-webhook-secret` (text); values come from the secret files |
| `jobs` → `multibranchPipelineJob` | creates the job `notes-devops` (see below) |

> Every `${...}` is filled in by JCasC from the secrets folder. Every `{{ ... }}` is filled in by Ansible (Jinja2) **before** the file reaches the server.

### The job definition, piece by piece

| Line | Meaning |
|---|---|
| `github { repoOwner, repository, repositoryUrl }` | which GitHub repository |
| `credentialsId('github-token')` | log in to the GitHub API with our token (5000 requests/hour instead of 60, and permission to set statuses) |
| `gitHubBranchDiscovery { strategyId(1) }` | build branches, but skip branches that already have an open PR (the PR build covers them) |
| `gitHubPullRequestDiscovery { strategyId(1) }` | build PRs **merged with main** (the result you would get after merging) |
| no fork discovery | PRs from other people's copies of the repo are ignored (security) |
| `orphanedItemStrategy` | when a branch is deleted, keep at most 10 old sub-jobs |
| `periodicFolderTrigger('1d')` | rescan once a day in case a webhook was missed |

## 6.8 The `Jenkinsfile` (Phase 6 version)

<sub>File: `Jenkinsfile`</sub>

```groovy
pipeline {
  agent any

  options {
    timestamps()
    ansiColor('xterm')
    disableConcurrentBuilds()
    buildDiscarder(logRotator(numToKeepStr: '20'))
    timeout(time: 20, unit: 'MINUTES')
  }

  environment {
    CI_PROJECT = "ci-${env.BRANCH_NAME.toLowerCase().replaceAll('[^a-z0-9]', '-')}-${env.BUILD_NUMBER}"
  }

  stages {
    stage('Lint & Test') {
      steps {
        sh 'docker compose -p "$CI_PROJECT" -f compose.ci.yml run --rm --build tests'
      }
    }
  }

  post {
    always {
      sh 'docker compose -p "$CI_PROJECT" -f compose.ci.yml down -v --rmi local --remove-orphans || true'
      cleanWs()
    }
  }
}
```

| Part | Meaning |
|---|---|
| `pipeline { }` | **declarative** pipeline: a fixed structure that is easy to read |
| `agent any` | run on any free executor (here: the controller) |
| `timestamps()` | time on every log line |
| `ansiColor('xterm')` | show colours from tools (npm, docker) |
| `disableConcurrentBuilds()` | one build per branch at a time |
| `buildDiscarder(logRotator(numToKeepStr: '20'))` | keep only the last 20 builds per branch (saves disk) |
| `timeout(20 min)` | a stuck build is stopped |
| `environment { CI_PROJECT = ... }` | a unique, lower-case name such as `ci-pr-6-3` (compose project names must be lower case; `replaceAll` turns `/` and other symbols into `-`) |
| `stage('Lint & Test')` | `docker compose ... run --rm --build tests`: builds the `test` image stage, starts Postgres, waits until it is healthy, runs `npm run lint && npm test`. The exit code decides ✓ or ✗ |
| `post { always { ... } }` | runs whether the build passed or failed: remove containers, volumes (`-v`) and the built image (`--rmi local`), then delete the workspace |

`BRANCH_NAME` and `BUILD_NUMBER` are set by Jenkins: for PR #6 build 3, `BRANCH_NAME=PR-6` and `BUILD_NUMBER=3`.

## 6.11 Problems and fixes

### `ValidationException: Value at 'value' failed to satisfy constraint: Member must have length greater than or equal to 1`
- **Cause:** the token was written into the `echo` command instead of being pasted at the hidden `read -s` prompt, and the whole block was pasted at once, so `read` swallowed the next line and `$GH_TOKEN` was empty.
- **Fix:** store the token through the AWS Console (6.9.2).
- **Security lesson:** a token that appears in a chat, a screenshot or a terminal recording counts as **leaked**: delete it on GitHub and make a new one.

### No status on the PR; the stored "token" was 252 characters and 3 lines long
- **Cause:** `--value "$(pbpaste)"` stores **whatever is in the clipboard** when Enter is pressed. The clipboard still held the copied commands, not the token.
- **How we found it:** `wc -c` (252 instead of 94) and `tr -d '[:alnum:]_' | od -c` (spaces, `$`, `(`, `)`, several `\n`).
- **Effect:** Jenkins could still **read** the public repo (scans worked), but it could not set commit statuses, so `gh pr checks` said `no checks reported`.
- **Fix:** paste the real token in Parameter Store (Console), check `wc -c` = 94, run `ansible-playbook playbooks/site.yml --limit jenkins` (new secret file → Jenkins restarts), push → ✓.

### `Hook already exists on this repository` (HTTP 422)
- **Cause:** the webhook command was run twice; the first run had already created it.
- **Fix:** nothing; the list shows one active hook.

### `Could not match supplied host pattern, ignoring: jenkins`
- **Cause:** `ansible` was run from the project root, where there is no `ansible.cfg`, so there was no inventory.
- **Fix:** always `cd infra/ansible` first.

### `curl: (43) A libcurl function was given a bad argument`
- **Cause:** the broken "token" contained line breaks, which are not allowed inside an HTTP header.
- **Fix:** store the correct token.

### First scan didn't see the new branch
- **Cause:** the scan ran when Jenkins started (before the push), and the push event was received while the token was broken.
- **Fix:** after the correct token: a new push (or **Scan Repository Now**) → the branch and PR-6 appeared and were built.

### The updated JCasC file didn't reach the Mac (`nothing to commit`)
- **Cause:** a file-sync glitch on my side: the old version was written again.
- **Fix:** written again and checked by size (2642 bytes) before committing.
